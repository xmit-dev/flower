Before you beginNode.js 22.18+macOS 15+ or Linux with glibc 2.35+x86-64 or Arm64

1. Install Flower

Make a project directory, download the server for your machine into it, and install the SDK, which includes the flower command line.

Terminal · new project
mkdir garden && cd garden

case "$(uname -sm)" in
  "Darwin arm64") target=aarch64-apple-darwin ;;
  "Darwin x86_64") target=x86_64-apple-darwin ;;
  "Linux aarch64") target=aarch64-unknown-linux-gnu ;;
  "Linux x86_64") target=x86_64-unknown-linux-gnu ;;
esac
curl -fsSL "https://github.com/xmit-dev/flower/releases/download/v@FLOWER_VERSION@/flower-@FLOWER_VERSION@-$target.tar.gz" |
  tar -xzf - --strip-components=1 "flower-@FLOWER_VERSION@-$target/flower"
./flower --version

echo '{ "type": "module" }' > package.json
npm install @flower-js/sdk
  • ./flower is the server: one executable, with no Node or other runtime needed. npx flower is the SDK's command line, which builds, deploys and calls apps.
  • Each release has an archive per platform, with the license, third-party notices and a .sha256 checksum. macOS builds aren't notarized: a server downloaded with a browser needs xattr -d com.apple.quarantine flower before it runs.
  • No build for your platform? Build from source.

2. Start a node

Pick an operator token and use it in every terminal.

Terminal 1 · garden
export FLOWER_ADMIN_TOKEN='local-development-secret'
./flower \
  --id 1 \
  --listen 127.0.0.1:7101 \
  --data .flower/node1

3. Initialize and deploy

In a second terminal, initialize the node, check for a leader, then download and deploy the app from the homepage walkthrough: a shared garden where seeds bloom after 5 seconds and wilt after 35.

Terminal 2 · garden
export FLOWER_ADMIN_TOKEN='local-development-secret'
npx flower init --members 1=127.0.0.1:7101

# Check that the initial election has produced a leader.
curl -fsS -H "Authorization: Bearer $FLOWER_ADMIN_TOKEN" \
  http://127.0.0.1:7101/raft/metrics

curl -fsSLO https://flower.xmit.dev/terrarium.ts
npx flower deploy terrarium.ts
  • Deploy once metrics show state: "Leader". UNAVAILABLE means the election is still settling; retry.
  • Run init only on a fresh cluster, never on a restarted data directory.
  • Callers of your methods don't need the operator token.

4. Call a method

Plant a seed, read the garden, then watch it bloom.

Terminal 2 · garden
npx flower call garden.plant '{"garden":"my-garden","id":"rose"}' \
  --request-id plant-rose
npx flower call garden.view '"my-garden"'
# value: { blooming: 0, flowers: { rose: "🌱" }, spacesLeft: 11 }

npx flower watch garden.view '"my-garden"'
# {"revision":3,"value":{"blooming":1,"flowers":{"rose":"🌼"},"spacesLeft":11}}
  • If a mutation times out, retry with the same --request-id.
  • A rejected call prints its failure and exits nonzero. Plant rose again under another request ID and you get flower: SPOT_TAKEN: That spot is already planted.
  • watch prints the value, then each change: the bloom, and 35 seconds after planting, the empty spot. It can skip intermediate commits. Stop it with Ctrl+C.

Next: call it from TypeScript

With the node still running, download the walkthrough's client and run it. It plants a seed with the typed client and follows the garden live.

Terminal 2 · garden
curl -fsSLO https://flower.xmit.dev/terrarium-client.ts
node terrarium-client.ts

Node runs TypeScript directly, and TypeScript checks every alias and argument against the app's types in your editor. Timers mean “not before”, so downtime can delay the bloom. Source: application and client.

Build from source

To work on Flower itself, or on a platform without a release build, clone the repository and build the SDK and server. You also need Rust 1.96+ and a C compiler.

Terminal
git clone https://github.com/xmit-dev/flower.git
cd flower
npm ci
npm run build
cargo build --release --bin flower

In a checkout the server is ./target/release/flower, and node sdk/cli.ts takes the place of npx flower. With Nix, nix run github:xmit-dev/flower -- --help builds and runs the server, and nix develop gives the pinned toolchain. The repository's examples/ directory has more apps to deploy.
